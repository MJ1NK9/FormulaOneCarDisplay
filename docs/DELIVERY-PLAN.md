# RB22 Web3D 交付路线图

> 从「能跑的作品集 demo」到「可交付的线上作品」的执行流程。
> 本文是**执行清单**，不是愿景：每完成一项就勾掉，并单独提交一次。
> 相关：[README](../README.md)（怎么跑）、[PROJECT_CONTEXT](../PROJECT_CONTEXT.md)（架构硬约束）。

---

## 1. 起点判断

| 维度 | 现状 |
| --- | --- |
| 工程完成度 | 高：渲染骨架、车模、展示间、8 个热点、加载与错误 UI 都已跑通，`vue-tsc` 零错误 |
| 可交付性 | 低：没有线上地址，36 MB 车模不在仓库里，别人拿到代码跑不起来 |
| 产品闭环 | 缺失：页面没有「关于我 / 联系方式 / 项目说明」，热点卡片就是终点 |
| 弱机兜底 | 不足：WebGL 初始化失败会白屏并卡在假进度；移动端取景未验收 |
| 工程可信度 | 不足：无 CI、无 lint、零测试、无错误上报 |
| 呈现 | 不足：README 是开发日志，`docs/` 里的截图没有被引用，没有技术叙事 |

**结论：不缺功能，缺闭环。** 所以按「先上线 → 再兜底 → 再质量 → 最后包装」推进，
不按功能清单推进。

---

## 2. 流程总览

```
P0 交付闭环 ──▶ P1 体验与质量 ──▶ P2 工程化 ──▶ P3 呈现与运营
（能不能用）      （好不好用）        （敢不敢改）      （传不传得开）
```

四条原则：

1. **先上线，再优化。** 没有 URL 的作品，优化得再好也没人看见。
2. **每个阶段独立可交付。** P0 结束就应该是一个能发出去的成品，而不是半成品。
3. **先修白屏，再谈帧率。** 失败路径的优先级永远高于性能调优。
4. **验收写死，不靠感觉。** 每一项都要有可复现的验收动作，做完打勾。

---

## 3. P0 — 交付闭环（必须）

**目标：一个陌生人拿到链接，30 秒内能打开、能玩、知道怎么联系作者。**

- [x] 代码与 36 MB 车模入库，`clone` 后可直接运行
- [x] README 重写：项目是什么、有什么、技术栈、AI Coding 说明
- [ ] 部署到静态托管（Vercel / Netlify），拿到公开 URL
- [x] 初始化失败兜底：WebGL 2 预检 + 场景创建 try/catch，失败给明确提示
- [x] 加载失败可重试（按钮），不要求用户自己刷新；显卡上下文丢失也有兜底
- [ ] 页面加入口：关于我 / GitHub / 邮箱 / 项目说明
- [ ] favicon + OG / Twitter 分享卡片
- [x] 车模授权确认：Sketchfab「2026 Redbull RB22」by Tyler_Dave，CC BY 4.0（需署名）
- [x] 页面署名：左上角作者 + 协议链接
- [ ] 商标使用边界确认（Red Bull / F1，公开商用前）
- [ ] 明确代码协议（LICENSE 或「保留所有权利」声明）

**验收线**

- 无痕窗口打开 URL，首屏 30 秒内出现车模；
- 禁用 WebGL（或低端机）时出现可读的错误说明，而不是无限加载；
- 页面上能点到作者联系方式；
- 微信 / LinkedIn 粘贴链接有标题和缩略图。

---

## 4. P1 — 体验与质量

**目标：中低端设备也能用，内容经得起推敲。**

- [ ] 移动端真机验收：竖屏取景、触摸旋转、卡片抽屉、内存占用
- [ ] 画质分级：低端设备降 DPR、关阴影、纹理降到 1K
- [ ] 模型压缩：Draco + KTX2（10.5 MB），或首屏低模 + 后台换高模
- [ ] 可访问性：卡片焦点管理（打开聚焦 / 关闭还焦）、axe 扫描、纯键盘全路径
- [ ] 浏览器矩阵：iOS Safari、Android Chrome、Firefox、集显
- [ ] 性能预算：记录首屏、FPS、draw call、显存，改动前后对比
- [ ] 内容校对：8 个热点文案逐条核对，出处从「FIA 总目录」细化到具体章节

**验收线**

- iPhone 12 / 中端安卓稳定 30 fps 以上；
- axe 无 critical 问题；
- 4G 网络首屏可交互 < 5 s；
- 每条规格数字都有可点开的出处。

---

## 5. P2 — 工程化

**目标：改代码不心虚，线上出问题看得见。**

- [ ] CI：push / PR 自动跑 `vue-tsc --noEmit` + `vite build`
- [ ] ESLint + Prettier + EditorConfig
- [ ] 测试三件套：热点配置校验（id 唯一 / 坐标非零 / source 存在）、坐标单位换算单测、Playwright 冒烟
- [ ] 轻量埋点：访问、热点点击、卡片关闭（Umami / Plausible）
- [ ] 错误上报：`window.onerror` + WebGL 失败事件
- [ ] 构建拆包：three / vue 走 `manualChunks`
- [ ] CHANGELOG + git tag + release note

**验收线**

- PR 不过 CI 不能合并；
- 线上 JS 错误能在 1 分钟内看到堆栈；
- `dist` 首包 gzip < 150 kB（模型另算）。

---

## 6. P3 — 呈现与运营

**目标：不看代码，也能在 3 分钟内讲清这个项目的价值。**

- [ ] README case study：hero GIF、架构图、3 个关键技术决策、优化前后对比
- [ ] 英文摘要（面向海外岗位 / 远程）
- [ ] 项目页 / 作品集站点互链
- [ ] 分享文案与预览图

**验收线**

- 面试官只读 README 就能问出好问题；
- 每个技术决策都能对应到一段代码或一张图。

## 8. 提交规范

- 一个 commit 只做一件事，信息用 Conventional Commits：
  `feat:` / `fix:` / `docs:` / `chore:` / `perf:` / `refactor:`
- 提交前必须跑 `npm run build`（内含 `vue-tsc --noEmit`）；
- 交付说明写清：改了哪些文件、对应哪个阶段、怎么手动验收；
- 不通过验收线不勾选、不声称完成。

## 9. 风险与待决

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| 车模授权 / 商标 | 公开部署可能被要求下架 | 已确认 CC BY 4.0（需署名）；页面已加署名，商标另行确认 |
| 36 MB 模型进 Git | 仓库变重，后续替换会膨胀历史 | 先直接提交保证可运行；后续换 CDN / LFS 时再迁移 |
| 部署平台选择 | Vercel 国内访问不稳定 | 备选 Netlify / Cloudflare Pages，或双部署 |
| 代码协议 | 无协议 = 别人不能合法复用 | 作者确认后再加 LICENSE |
